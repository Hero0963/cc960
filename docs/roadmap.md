## 下一步

1. **引擎自我對弈：量測真實和棋率**（最高優先——**唯一能驗證核心假設的實驗**）
   - 為什麼非做不可：引擎的**評估值回答不了這題**。同材料下 `wdl` 是 `cp` 的確定性函數，不是獨立觀測。必須實際下棋。
   - 做法：標準開局與平衡版各下數百局（每步固定節點數），統計勝／和／負。以 16 worker、每局約 150 秒估算，800 局約 2 小時。
   - Done 條件：兩組分勝負率的對照（附信賴區間），寫進 `rationale.md §一`。
   - 風險：引擎自我對弈的和棋率與人類對局不是同一回事，結論要標註。

2. **擴大審局範圍：完整池的進兵局面**
   - 目前只審過輕量版（兵全原位）。初步跡象顯示進兵的局面可能同時**更尖銳也更失衡**，但 n=1，需要擴大取樣。
   - Done 條件：完整池抽樣 100–150 局的分布，決定競賽池要不要納入進兵局面。

3. **實戰試玩**（低成本、高資訊量）
   - 從平衡版抽 10 局自戰或找棋友下，記錄主觀感受：新鮮度、守和難度、有沒有哪類局面一開始就明顯難受。
   - Done 條件：`docs/playtest.md`（新檔）記下每局編號＋一兩句感想；發現規則問題就回報成 issue。

4. **對外文章＋社群曝光**

## 已定案，不要再重開的決策

| 決策 | 理由（詳見 rationale.md） |
|------|--------------------------|
| 明置隨機開局，不做暗子 | 暗子＝揭棋的生態位，會引入運氣與隱藏資訊 |
| 不加大棋盤 | 歷史先例全數失敗；將棋證明機制比盤面關鍵 |
| 紅黑點對稱（非軸對稱） | 棋手視角的「公平相同」；且使合法池大增、將位隨機成為可能 |
| 象／兵限「預走合法步」可達點 | 保住棋味與殘局知識 |
| 將帥固定中路（v3） | 中路自對稱最簡；將位隨機留給 v4 |
| 演示頁維持單檔、零相依、可離線 | GitHub Pages 直接吃 `docs/index.html`；不引入框架或 bundler |
| **不做「紅黑兩邊完全不對稱」** | 公平性退化為只能逐局實測；池規模 10¹¹ 使編號與審局失效（spec.md §11） |
| **不改回軸對稱為主規格** | 同路正面相對助長兌子求和；軸對稱版保留為新手／展示池 |
| **兵維持可進一格** | 固定原位只剩 33,236 局，且進兵是結構多樣性的主要來源（spec.md §11） |
| **完整版不改密集編號** | 建索引需先枚舉 139 萬，與單檔離線頁衝突；人用場景由小池的 `#1..#N` 覆蓋（spec.md §3） |
| 賽制＝雙局換色（對抗賽）／選局選邊（單局） | 不採 ban 制：解決不了先手優勢，且會把局面推向保守（rationale.md §五） |
| 授權＝程式 MIT ＋ 文件 CC BY 4.0 | 文件與規則敘述要顯著署名；玩法本身著作權不保護 |
