## 下一步

1. **Pikafish 審局池**（最高優先，也是最好的文章題材）
   - 目標：量測合法開局的紅方先手優勢分布，產出接近平衡的「競賽池」建議。
   - 做法：抓 Pikafish（UCI 引擎，放 `engine/`，已在 `.gitignore`）→ 寫 `scripts/eval-pool.js` 把局面轉成 FEN 餵引擎（固定深度，例如 depth 20，背景批跑）→ 先抽樣 1,000–2,000 局看分布形狀，再決定要不要跑更大樣本。
   - **需要先解的技術債**：目前沒有 FEN 輸出。第一步是在 `src/setup.js` 加 `toFen(bd)`（象棋 FEN 格式，紅方先行），並加測試：標準開局要輸出公認的起始 FEN。
   - Done 條件：拿到分布（平均／最大／最小 centipawn、標準差），選出「|評估| ≤ 某閾值」的子集當競賽池，數字與方法寫進 `spec.md` 新增一節＋更新 `rationale.md §五 公平性`。
   - 風險：象棋引擎對「非標準開局」的評估未必可靠（NNUE 訓練分布外），結論要標註這個限制。

2. **實戰試玩**（低成本、高資訊量）
   - 抽 10 局自戰或找棋友下，記錄主觀感受：新鮮度、守和難度、有沒有哪類局面一開始就明顯難受。
   - 優先試「有進兵」與「互襲」的局面（這兩類是 v3 才大量出現的）。
   - Done 條件：`docs/playtest.md`（新檔）記下每局編號＋一兩句感想；發現規則問題就回報成 issue。

3. **對外文章＋社群曝光**

## 已定案，不要再重開的決策

| 決策 | 理由（詳見 rationale.md） |
|------|--------------------------|
| 明置隨機開局，不做暗子 | 暗子＝揭棋的生態位，會引入運氣與隱藏資訊 |
| 不加大棋盤 | 歷史先例全數失敗；將棋證明機制比盤面關鍵 |
| 紅黑點對稱（非軸對稱） | 棋手視角的「公平相同」；且使合法池大增、將位隨機成為可能 |
| 象／兵限「預走合法步」可達點 | 保住棋味與殘局知識 |
| 將帥固定中路（v3） | 中路自對稱最簡；將位隨機留給 v4 |
| 演示頁維持單檔、零相依、可離線 | GitHub Pages 直接吃 `docs/index.html`；不引入框架或 bundler |
