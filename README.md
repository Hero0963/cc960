# cc960 — 隨機開局象棋

> 借鑑西洋棋 Chess960（Fischer Random）的中國象棋變體：**走法、吃法、勝負規則 100% 不變，只把開局擺法隨機化**。

**🎲 開局盤面產生器：<https://hero0963.github.io/cc960/>**
單頁、免安裝、無後端、可離線；按一下就產生一個開局盤面，並附 FEN 與可分享的連結。
（產生器只負責生盤面，**不在網頁上下棋**。）

## 產生的是什麼

產生器吐出的每一個盤面，都是**標準象棋盤、標準 32 子、在標準象棋規則下完全合法、可以直接下完一整局**的局面：

- 棋盤、棋子、走法、吃法、將軍、勝負判定**一律照原本的中國象棋**，沒有新棋子也沒有新規則。
- 每個子都放在「它自己走得到」的位置上，不是亂丟——所以馬還是馬、象還是象，中局手筋與殘局知識完全沿用。
- **明置、零運氣、零隱藏資訊**：開局前雙方就看得見全部棋子（這一點和暗子類的變體不同）。

換掉的只有一件事：**大家從哪個陣形開始**。

## 擺法規則（6 條）

1. **走法與勝負規則完全同標準象棋**，只有初始擺放不同。
2. **紅黑點對稱**：黑方擺法＝紅方旋轉 180°（紅 (r,c) ↔ 黑 (9−r, 8−c)）。
   *從各自座位看，雙方陣形一模一樣*——紅「一路」兵進，對應黑「1路」卒進（不是同一直線）。
3. **將帥居中路九宮底線，雙士貼於兩側**（中路自對稱；中路必有兵卒相隔，永不照面）。
4. **象 2 子**隨機置於「原軌道」5 點中任 2 點：底線 c/g、宮頂線 a/e/i。象離開底線時，該底線位留空。
5. **馬 2 子、車 2 子**隨機分配剩餘的底線非九宮路；**炮 2 子**隨機置於宮頂線任 2 路（不可疊上象）。
6. **兵 5 子**各路獨立：原位或前進一格。

再加一道**首著靜置檢定**，剔除「開局就能白吃大子」的失衡局面。

> 為什麼象只能放那 5 點、兵只能進一格？**「預走合法步」原則**：所有起始位置都必須是「開局前在己方領土走原本合法步」可以到達的點。變的是出發陣形，不變的是每個子的本性——所以棋味與殘局知識完整保留。
> （v3 另含河沿 c5/g5，v4 拿掉——河頭象實戰極罕見，且實測對局面平衡毫無影響。）

**為什麼是點對稱而不是左右鏡像**：鏡像下雙方強翼同路正面相對，最省力的下法就是硬碰硬兌子——正好走回和棋軌道。點對稱讓強翼錯開，天然形成兩翼互攻。（Chess960 本身是鏡像；點對稱是 cc960 的設計差異。）

規則細節、編號系統、已否決的方向以 **[docs/spec.md](docs/spec.md)**（規格正本）為準；
程式怎麼組起來的見 **[docs/architecture.md](docs/architecture.md)**；
問題數據、方案比較與公平性討論見 **[docs/rationale.md](docs/rationale.md)**。

## 怎麼用產生器

用**勾選**決定哪些棋種要隨機；沒勾的就釘在標準開局的位置（象 c1/g1、馬 b/h、車 a/i、炮 b/h、兵全原位）。

| 想要的效果 | 勾法 | 局數 | 平衡率 |
|------|------|------|------|
| **日常對局（建議預設）** | 象、炮、兵 | 4,272 | **60%** |
| 陣形變化最多 | 象、車、炮、兵 | 14,592 | 48% |
| 幾乎每局都平衡 | 象、兵 | 160 | **92%** |
| 全部放開 | 全勾 | 172,848 | 32% |

「平衡率」＝ 隨機抽一局、紅方先手優勢在 40 釐兵以內的機率（Pikafish depth 40 取樣實測，見下）。

> ⚠ **馬和車不要同時勾**。實測發現這是失衡的主因：馬車都放開時只有 **28%** 的局面平衡，不同時放開則有 **71%**。
> 原因是底線洗牌後車一落到 **b/h 路**（炮的原始路）就站在自家炮的正下方，形成車炮同線的強襲陣——
> 車落 b/h 時平衡率只有 16%，不落 b/h 則有 62%。首著檢定只看一步吃子，攔不住這種陣形性優勢。
> 想動馬車又要平衡，就用下面引擎驗證過的 70 局名單。

五個勾選共 **32 種組合，每一種都必定含標準開局**，所以任何設定都能對照「跟標準只差在哪」。
有些組合是退化的（例如只勾「馬」時，象與車釘住後底線只剩 b/h 給馬），頁面會標「此設定下無可選位置」。
小池會在頁面上直接全枚舉並顯示局數；全勾時局面太多，改為「即抽即驗」（隨機抽、當場檢定、不合法就重抽）。

每產生一局，頁面會給出該局的 **FEN**（象棋界通用的局面字串，可直接貼進象棋軟體或引擎）與**帶編號的連結**（`?id=3872`），對方打開就是同一局。

**平衡率怎麼測的**：32 種勾選組合各取樣 `min(25, N)` 局，去重 454 局交給 **Pikafish 2026-01-02** 跑固定**深度 40**（單執行緒、置換表 1024 MB、MultiPV 1），統計 |評估| ≤ 40 釐兵的比例（2026-08-01）。
n=25 的信賴區間偏寬，單組之間的細微排序不具統計意義；上表的「馬車」結論則有 181 vs 486 筆樣本支撐，信賴區間不重疊。完整分布見 [docs/spec.md §8.4](docs/spec.md)。

**已驗證的平衡子池**：把「只隨機馬車炮」那 216 局全部交給同一引擎跑**深度 40**，逐局取紅方先手優勢，保留 **≤ 40 釐兵**者共 **70 局**（驗證日期 2026-07-25，v4 改動後 70 局全數仍合法）。
現代引擎的評估已正規化到勝率，**100 釐兵 ≈ 50% 勝率**，所以 40 釐兵約當紅方勝率一成——與標準開局（18 釐兵，也在池內）同級。
這 70 局不只公平，**下法選擇也多**：引擎的最佳著與第三選擇平均只差 10 釐兵，沒有唯一解。完整名單與方法見 [docs/spec.md §8](docs/spec.md)。

## 賽制建議

隨機開局的已知問題是**各局面的先手優勢不均**。cc960 的實測比 Chess960 嚴重得多——標準差 101 vs 12、最大 485 vs 81 釐兵（見上）。所以**賽用池一定要篩過**，不能直接抽全池。建議做法：

| 場景 | 做法 |
|------|------|
| 對抗賽（能下兩局） | **同一局面連下兩局、雙方換色** — 直接對消先手優勢，FIDE 世界 Fischer Random 賽現行做法 |
| 單局賽事 | **抽 3 局 → 甲方選局面 → 乙方選紅黑** — 切蛋糕原理：甲有動機選最平衡的局面，否則好的一邊會被乙挑走 |
| 共同配套 | 賽用池採**引擎驗證過的 70 局平衡子池**（見 [docs/spec.md §8.3](docs/spec.md) 的編號名單）；開賽前 15 分鐘才公布局面，封殺賽前準備 |

不建議「雙方各否決一局」的 ban 制：它解決不了先手優勢，且雙方各刪掉自己最不喜歡的之後，剩下的是「兩人都不討厭」的局面，趨向保守平衡——與壓低和棋率的目標相反。詳見 [docs/rationale.md §五](docs/rationale.md)。

## 開發

無執行期相依；只有測試需要 jsdom。

```bash
npm install       # 只裝 jsdom（測試用）
npm run build     # src/ → docs/index.html（單檔產生器頁）
npm test          # build ＋ 22 項無頭 DOM 迴歸測試
npm run count     # 全空間枚舉，重算合法局面數（約 10 秒，改規則後必跑）
npm run stats     # 特徵統計＋終端機渲染示範局面
```

```
src/rules.js      象棋走法引擎（與隨機開局無關，就是一副普通象棋）
src/setup.js      隨機開局擺位產生器＋編號系統＋首著靜置檢定＋FEN 輸出
src/ui.js         產生器頁互動（棋盤 SVG、勾選式產生器、FEN 與連結分享）
src/shell.html    產生器頁外殼（HTML/CSS/文案，含三個注入點）
scripts/build.js  組裝：shell ＋ 三個 js 內聯 → docs/index.html
docs/index.html   建置產物（GitHub Pages 直接吃這個檔；請勿手改）
```

`docs/index.html` 是**建置產物**：要改產生器頁請改 `src/`，再 `npm run build`。
走法引擎本身的迴歸保護在 `npm run count`——合法局面數等期望值一變，就代表引擎行為被改壞了。
開發流程、PR 與 issue 慣例見 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 現況與後續

**現況**：規格 v4 與產生器可用、22 項測試全過。「只隨機馬車炮」那 216 局已用引擎全跑過，產出 70 局的平衡子池。
未實作長打（長將、長捉）判例；未實測和棋率。

> 關於和棋率：本專案的目標是**打擊背譜**（讓賽前準備開局的邊際效益下降），不是把和棋率當作 KPI。
> 量測真實和棋率需要大量引擎自我對弈，目前**刻意不做**；優先確認的是「每種勾選組合都有足夠的平衡局面可用」。

**下一步**（完整版含 done 條件與已定案決策 → [docs/roadmap.md](docs/roadmap.md)）

1. **各勾選組合的平衡率地圖**：32 種組合各取樣評估，回答「哪些組合值得推薦當賽用池」。
2. 對值得的組合做全池評估，產出該組合的平衡名單。
3. 實戰試玩：抽局自戰／找棋友對弈，主觀評估新鮮度與守和難度。
4. 對外文章與社群曝光。
