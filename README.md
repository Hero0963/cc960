# cc960 — 隨機開局象棋

> 借鑑西洋棋 Chess960（Fischer Random）的中國象棋變體：**走法、吃法、勝負規則 100% 不變，只把開局擺法隨機化**。

**🎲 開局盤面產生器：<https://hero0963.github.io/cc960/>**
單頁、免安裝、無後端、可離線；按一下就產生一個開局盤面。

## 產生的是什麼

產生器吐出的每一個盤面，都是**標準象棋盤、標準 32 子、在標準象棋規則下完全合法、可以直接下完一整局**的局面：

- 棋盤、棋子、走法、吃法、將軍、勝負判定**一律照原本的中國象棋**，沒有新棋子也沒有新規則。
- 每個子都放在「它自己走得到」的位置上，不是亂丟——所以馬還是馬、象還是象，中局手筋與殘局知識完全沿用。
- **明置、零運氣、零隱藏資訊**：開局前雙方就看得見全部棋子（這一點和暗子類的變體不同）。

換掉的只有一件事：**大家從哪個陣形開始**。

## 擺法規則（6 條）

1. **走法與勝負規則完全同標準象棋**，只有初始擺放不同。
2. **紅黑點對稱**：黑方擺法＝紅方旋轉 180°（紅 (r,c) ↔ 黑 (9−r, 8−c)）。
   *從各自座位看，雙方陣形一模一樣*——紅「一路」兵進，對應黑「1路」卒進（不是同一直線）。
3. **將帥居中路九宮底線，雙士貼於兩側**（中路自對稱；中路必有兵卒相隔，永不照面）。
4. **象 2 子**隨機置於「原軌道」7 點中任 2 點：底線 c/g、宮頂線 a/e/i、河沿 c/g。象離開底線時，該底線位留空。
5. **馬 2 子、車 2 子**隨機分配剩餘的底線非九宮路；**炮 2 子**隨機置於宮頂線任 2 路（不可疊上象）。
6. **兵 5 子**各路獨立：原位或前進一格（不可疊上河沿象）。

再加一道**首著靜置檢定**，剔除「開局就能白吃大子」的失衡局面。

> 為什麼象只能放那 7 點、兵只能進一格？**「預走合法步」原則**：所有起始位置都必須是「開局前在己方領土走原本合法步」可以到達的點。變的是出發陣形，不變的是每個子的本性——所以棋味與殘局知識完整保留。

**為什麼是點對稱而不是左右鏡像**：鏡像下雙方強翼同路正面相對，最省力的下法就是硬碰硬兌子——正好走回和棋軌道。點對稱讓強翼錯開，天然形成兩翼互攻。（Chess960 本身是鏡像；點對稱是 cc960 的設計差異。）

規則細節、編號系統、已否決的方向以 **[docs/spec.md](docs/spec.md)**（規格正本）為準；
程式怎麼組起來的見 **[docs/architecture.md](docs/architecture.md)**；

## 關鍵數字

| 項目 | 數值 |
|------|------|
| **合法開局** | **339,484**（標準開局也在池內，編號 **3872**） |
| 編號空間 | 1,389,312（約 24% 合法） |
| 輕量版（象、兵固定，只隨機車馬炮） | **216** 局，全數合法（標準開局＝ #122） |
| **平衡版（引擎驗證過的競賽池）** | **70** 局（標準開局＝ #31） |
| 軸對稱版（每方自身以中線左右對稱） | **146** 局（標準開局＝ #21） |
| 紅方首著機動力 | 19–53 著，平均 36.7（標準開局 44 著） |
| 局面特徵 | 90.2% 含進兵、99.0% 含高位象 |

四種池都做在同一頁的下拉選單裡：
**軸對稱版**棋形最像標準棋（新手與展示）→ **平衡版**引擎驗證過、公平且下法多（**比賽用**）→ **輕量版**編號最好記 → **完整版**變化最多。

**平衡版怎麼來的**：把輕量版 216 局全部交給象棋引擎 **Pikafish 2026-01-02** 跑固定**深度 40**（單執行緒、置換表 1024 MB、MultiPV 1），逐局取紅方先手優勢，保留 **≤ 40 釐兵**者共 70 局（驗證日期 2026-07-25）。
現代引擎的評估已正規化到勝率，**100 釐兵 ≈ 50% 勝率**，所以 40 釐兵約當紅方勝率一成——與標準開局（18 釐兵，也在池內）同級。
這 70 局不只公平，**下法選擇也多**：引擎的最佳著與第三選擇平均只差 10 釐兵，沒有唯一解。完整分布與方法見 [docs/spec.md §8](docs/spec.md)。

## 賽制建議

隨機開局的已知問題是**各局面的先手優勢不均**。cc960 的實測比 Chess960 嚴重得多——標準差 101 vs 12、最大 485 vs 81 釐兵（見上）。所以**賽用池一定要篩過**，不能直接抽全池。建議做法：

| 場景 | 做法 |
|------|------|
| 對抗賽（能下兩局） | **同一局面連下兩局、雙方換色** — 直接對消先手優勢，FIDE 世界 Fischer Random 賽現行做法 |
| 單局賽事 | **抽 3 局 → 甲方選局面 → 乙方選紅黑** — 切蛋糕原理：甲有動機選最平衡的局面，否則好的一邊會被乙挑走 |
| 共同配套 | 賽用池採**平衡版**（引擎驗證過的 70 局，密集編號 #1–#70）；開賽前 15 分鐘才公布局面，封殺賽前準備 |

不建議「雙方各否決一局」的 ban 制：它解決不了先手優勢，且雙方各刪掉自己最不喜歡的之後，剩下的是「兩人都不討厭」的局面，趨向保守平衡——與壓低和棋率的目標相反。詳見 [docs/rationale.md §五](docs/rationale.md)。

## 開發

無執行期相依；只有測試需要 jsdom。

```bash
npm install       # 只裝 jsdom（測試用）
npm run build     # src/ → docs/index.html（單檔演示頁）
npm test          # build ＋ 20 項無頭 DOM 迴歸測試
npm run count     # 全空間枚舉，重算合法局面數（約 25 秒，改規則後必跑）
npm run stats     # 特徵統計＋終端機渲染示範局面
```

```
src/rules.js      象棋走法引擎（與隨機開局無關，就是一副普通象棋）
src/setup.js      隨機開局擺位產生器＋編號系統＋首著靜置檢定
src/ui.js         演示頁互動（棋盤 SVG、走子、局面池切換）
src/shell.html    演示頁外殼（HTML/CSS/文案，含三個注入點）
scripts/build.js  組裝：shell ＋ 三個 js 內聯 → docs/index.html
docs/index.html   建置產物（GitHub Pages 直接吃這個檔；請勿手改）
```

`docs/index.html` 是**建置產物**：要改演示頁請改 `src/`，再 `npm run build`。
開發流程、PR 與 issue 慣例見 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 現況與後續

**現況**：規格與產生器可用、20 項測試全過。**先手優勢分布已用引擎量測完成**（輕量版 216 局全跑，見上），並據此產出平衡版 70 局。
尚未實測和棋率（引擎評估值無法回答這個問題，需要實際對弈統計），未實作長打（長將、長捉）判例。

**下一步**（完整版含 done 條件與已定案決策 → [docs/roadmap.md](docs/roadmap.md)）

1. **引擎自我對弈**：從標準開局與平衡版各下數百局，統計**真實**的勝／和／負——這是唯一能驗證「和棋率是否下降」的辦法。
2. 擴大審局：把完整版（含進兵的局面）也納入評估，看能否找到更豐富的平衡局面。
3. 實戰試玩：抽局自戰／找棋友對弈，主觀評估新鮮度與守和難度。
4. 線上對弈版＋簡單 AI。
